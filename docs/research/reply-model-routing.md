# 回复供应商路由

在 WebUI 的「模型配置 → 任务 → 回复模型」中配置「供应商路由提示词」。先把允许使用的模型加入该任务的模型列表，再填写自然语言规则，例如：

> 技术问题使用 DeepSeek，日常交流使用 Aliyun。需要指定某个模型时使用其配置名称。

供应商名称以当前实例配置为准。Planner 会看到规则，以及回复模型池中每个模型对应的供应商，并通过 reply 工具的 `reply_model` 参数选择本次模型。模型条目关联的供应商决定实际请求地址、鉴权和客户端类型。

提示词为空时关闭路由。规则没有匹配时 Planner 可以省略 `reply_model`，继续使用该任务原有的 random、balance 或 sequential 策略。显式选择时只调用所选模型；如果请求失败，沿用现有错误报告，不会自动改用其它供应商。模型级温度、输出限制和任务级参数仍按原有规则生效。

后端拒绝不在当前回复模型池内的名称和非字符串参数。路由只作用于本次回复，不修改全局模型列表。插件的 `maisaka.replyer.before_request` Hook 仍可按原有契约覆盖模型选择；Hook 抛错时保留本次 Planner 已选择的模型。

对应 TOML 字段为 `model_task_config.replyer.routing_prompt`。首次部署需要重启后端并使用更新后的 WebUI；后续规则通过现有模型配置保存/热重载链路更新，后续生成的 reply 工具声明使用新配置。该提示词由 Planner 解释，不是确定性的关键词匹配器，也不应作为权限隔离边界。

默认模板留空。本次没有替各实例写入业务路由规则、变更运行模型池或切换供应商地址。

验证覆盖：Planner 工具声明随配置更新；模型候选校验；连续回复之间选择隔离；Hook 异常时选择保留；后端保存与清空并触发重载；前端输入、清空、任务切换及现有自动保存链路。
